# AGENTS.md: working on and with TurretCAM

## Programming a part for a machine (no code changes)

1. Write a job file (`*.tcam.json`, schema below), or start from `examples/`.
2. `tcam build job.tcam.json out\NNNN.CNC --svg out\NNNN.svg`. It must print `ok=true`. It refuses to write a program that has errors.
3. Look at the SVG. Check that every hole, opening and outline is where the drawing says.
4. Hand off: the `.CNC`, the SVG, the program number, sheet and material, clamps, ETIME, the tools used, the full `tcam build` output, and anything the drawing asked for that wasn't supported.
5. Say plainly that the program hasn't run on the machine. The operator dry-runs it first.

### Rules

- Never hand-write or hand-edit G-code. Change the job and rebuild.
- Program with the shop's own profile (`TURRETCAM_HOME`), never `profiles/demo`: the demo turret load is made up.
- Only use tools that `tcam turret` lists. STALE tools (unused for over a year) aren't picked automatically. Ask before pinning them in `profiles/<p>/machines/<m>/turret_override.json`.
- Keep features clear of the clamp strip: at least 3.4" above the bottom edge near the clamps. Auto-nest leaves a 3.5" strip.
- Hit centres must stay within X ≤ 97.07 and Y ≤ 48.78. Repositions aren't generated.
- Ask the shop which program numbers (O-numbers) are free. The profile's `next_program_number` is only a suggestion.

### Job file

```jsonc
{
  "name": "2500376 ARK DEAD FRONT", "job": "2500376 ARK CUNY DEAD FRONT",   // job = CNC comment
  "machine": "m1225", "program_number": 9002,
  "sheet": {"x": 96, "y": 48, "thickness": 0.0315, "material": "ST 42", "qty": 1},
  "clamps": null,                                  // null = automatic, or [12, 48, 80]
  "parts": [{
    "id": "P1", "name": "Dead front", "outline": {"type": "rect", "w": 36, "h": 20, "tabs": true},
    "features": [
      {"type": "hole", "x": 1, "y": 1, "dia": 0.25},
      {"type": "hole", "x": 8, "y": 12, "dia": 4.125},                       // nibbled + slug destroyed
      {"type": "slot", "x": 2, "y": 10, "length": 0.5, "width": 0.25, "vertical": false},
      {"type": "rect", "x0": 5, "y0": 4, "x1": 32, "y1": 6.3125, "tabs": true}, // window
      {"type": "grid", "x": 20, "y": 13, "dx": 0.5, "dy": 1.25, "nx": 13, "ny": 4, "shape": {"kind": "OB", "w": 0.188, "h": 1.0}},
      {"type": "bolt_circle", "x": 20, "y": 10, "r": 1.5, "n": 6, "dia": 0.25, "start": 0},
      {"type": "hit", "x": 0.4, "y": 0.4, "tool": "SQ-0.75-M", "angle": 0}     // corner notch etc.
    ]}],
  "placements": [{"part": "P1", "x": 1.5, "y": 4.0, "rot": 0}],
  "options": {"tab": 0.025, "tab_every": 24, "min_overlap": 0.06, "allow_stale_tools": false}
}
```

Units are inches. Each part has its own origin at its lower-left corner. A placement puts the part's lower-left corner at (x, y) on the sheet, rotated by 0/90/180/270. Outline edges that sit on the sheet edge aren't cut. `tcam nest job.tcam.json --part P1=4` fills the placements automatically. `tcam import drawing.dxf --into job.tcam.json` (or `.dwg`; DWG is read built in through acadrust, no ODA needed) adds a part from a drawing. It works best on flat-pattern drawings. On full shop drawings the title block can become the outline. Unrecognised geometry comes in as `contour` features, which aren't punched: tell the user about them.

## Changing the code

- `cargo test --release`. With `TURRETCAM_ARCHIVE` pointing at a real program archive and `TURRETCAM_HOME` at the profile folder of the machine that ran it, this also re-emits every archived program and rebuilds the shop's examples against their archived `.CNC`. Those tests must keep passing. They're what prove the output format.
- The output format lives in `crates/turretcam-core/src/writer.rs` and `fmt.rs`. Don't change it without the archive test.
- Code semantics are documented in `docs/STRIPPIT_GCODE.md`. Feature strategies are in `cam.rs`, and each one cites the archive convention it copies.
- Machine data is generated by `tcam machine-from-lvd`. Don't edit `machine.json` or `turret.json` by hand. Use `turret_override.json` for the real turret load.
- UI: `crates/turretcam-app/src/` has `theme.rs` (palette, fonts, widget style), `icons.rs` (Phosphor glyph codes and hand-drawn CAM tool icons; fonts are bundled in `crates/turretcam-app/fonts/`), `widgets.rs` (cards, buttons, chips, stat tiles), and one file per step: `parts_view.rs`, `sheet_view.rs`, `program_view.rs`, `machine_view.rs`. App state, undo/redo and the top bar are in `app.rs`. Reuse the widgets and theme colours instead of styling inline.
- Screenshots for checking UI changes: `powershell -File scripts\screenshot.ps1 -Exe target\release\turretcam.exe -Out shot.png -AppArgs "examples\meter_cover_2up.tcam.json --generate --sim 210"`. The startup flags are `--step parts|sheet|program|machine`, `--generate`, `--sim N`, `--select N`, `--new-part` and `--station N`.
- Adding a machine: unzip its LVD `... - V31 - SETUP.exe` (it's a ZIP), run `tcam machine-from-lvd` with its post (`PSTSTR02` for the FC1000 XP/20 and CAP 1000) and its archive, and add it to the profile's `machines`. The XP and CAP use a different post (PSTSTR02), so the writer needs a second dialect first. Check it against that machine's program archive with a round-trip test before using it.
